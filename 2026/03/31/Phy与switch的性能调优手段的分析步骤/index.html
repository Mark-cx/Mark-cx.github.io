Phy 与 switch 的性能调优手段的分析步骤

发表于 2026-03-31 更新于 2026-04-01 分类于 驱动调试 Changyan：
这是一个典型的“数据面瓶颈定位 + 控制面一致性验证”的问题。你现在的场景（MTK + 外挂 switch + USXGMII + 多速率 PHY）属于中高复杂度链路，调优必须有体系，否则很容易误判。

一、整体方法论（先建立框架）

核心思路：

物理层 -> PCS/SerDes -> MAC -> Switch -> 队列/流控 -> CPU -> 协议栈

每一层必须回答 3 个问题：

  • 是否正常工作（功能）
  • 是否跑满（性能）
  • 是否匹配（配置一致性）

二、Step 1：物理层（PHY）—— 先确认链路质量

1) 看协商结果（你已经做了）

关注：

  • Speed（是否降速）
  • Duplex（必须 full）
  • Auto-neg（是否开启）

2) 看 PHY 误码 / 健康状态

重点字段（不同 PHY 名字不同）：

  • crc errors
  • symbol errors
  • alignment errors

判断：

  • 有误码 -> 物理层问题（线材 / 模块 / SI）
  • 无误码 -> 进入下一层

3) MDIO 寄存器级分析（进阶）

（特别是你用 RTL8261 / YT 系列）

重点看：

  • Clause45 AN 状态
  • Link partner ability
  • FEC 状态

三、Step 2：SerDes / PCS（关键瓶颈点）

你是：

USXGMII / 10GBase-KR / SGMII

这是最容易出性能问题的层。

关键检查点：

1) PCS 是否 lock

2) 是否发生速率 fallback

典型现象：

  • 支持 10G -> 实际 1G

原因：

  • Training 失败
  • AN 不匹配
  • FEC 不一致

3) FEC（前向纠错）

10G 链路常见：

  • RS-FEC
  • BASE-R FEC

不匹配会：

  • 丢包
  • 重传
  • 吞吐下降

四、Step 3：MAC 层（最容易被忽略）

1) 流控（你当前已经踩坑）

关键：

  • RX/TX pause 是否开启

判断：

状态 结果
无流控 TX 掉速 / 丢包
单向流控 严重不对称
双向流控 最稳定

2) MAC FIFO / 队列

关注：

  • tx_fifo_errors
  • rx_fifo_errors
  • queue drops

五、Step 4：Switch（YT9224 / MTK switch）

这是你当前架构的核心性能瓶颈点。

1) 端口速率一致性

必须保证：

  • CPU 口 = 10G
  • 上行口 = 10G
  • 下行口 >= 瓶颈

否则：

  • 内部拥塞

2) Switch buffer

YT9224 特点：

  • Buffer 有限
  • 无流控时容易爆

3) Port queue / 调度

看：

  • 是否启用 QoS
  • WRR / SP 调度

4) Switch <-> CPU 链路

你 DTS：

fixed-link 10G

风险：

  • 实际没跑到 10G（但内核认为是 10G）
  • 导致严重丢包

六、Step 5：数据面测试（iperf3 方法论）

正确测试方式：

1) 单向

2) 双向（你之前问题）

3) 多流

判断逻辑：

现象 结论
RX 正常，TX 低 无流控
双向都低 带宽瓶颈
抖动大 Buffer 不足

七、Step 6：CPU & 中断

1) 看 CPU

2) 看中断分布

判断：

  • 是否单核打满

3) RPS/XPS

八、Step 7：驱动 & 内核（你这个很关键）

你是：

  • MTK mtk_eth
  • phylink
  • 外挂 switch

关键检查点：

1) phylink 状态

是否正确传递：

  • speed
  • pause
  • duplex

2) 是否使用硬件 offload

3) DSA /swconfig 差异

  • swconfig -> CPU 压力大
  • DSA -> 更好

九、典型问题模式（直接对号入座）

模式 1（你当前情况）

  • RX 1.7G
  • TX 200M

结论：

  • 流控未生效

模式 2

  • 只跑 1G

结论：

  • AN / PCS / 模块不匹配

模式 3

  • 双向都低

结论：

  • CPU /switch 瓶颈

十、标准调优流程（建议你照这个走）

  1. ethtool -> 确认速率
  2. ethtool -a -> 确认流控
  3. PHY 寄存器 -> 确认 AN/FEC
  4. dmesg -> 看 link 变化
  5. iperf3 -> 单 / 双向验证
  6. switch port -> 确认无瓶颈
  7. CPU / 中断 -> 排除软件瓶颈

十一、给你的针对性建议（结合你现状）

你当前已经确认：

  • Link OK
  • 只有 1G
  • Flow control OFF

下一步优先级：

1) 先解决流控

2) 再查为什么不是 10G

重点看：

  • 对端设备
  • SFP 模块
  • USXGMII / PHY 配置

总结（一句话）

有线 PHY + switch 调优的核心不是提速，而是保证每一层（PHY -> PCS -> MAC -> Switch）能力一致且流控闭环成立，否则一定出现你现在这种带宽严重不对称的问题。
