linux 操作指令

发表于 2026-04-01 分类于 linux指令 Changyan：
记录一些linux指令。

温度查询

最简单正确方式（直接用）

cat /sys/devices/virtual/thermal/thermal_zone0/temp

你当前输出：

53557

👉 换算：

53.6°C
✅ 一行命令（自动换算）
awk ‘{printf “%.1f°C\n”, $1/1000}’ /sys/devices/virtual/thermal/thermal_zone0/temp

输出：

53.6°C
⚠️ 但要确认是不是 CPU（建议做一次）

不同平台 thermal_zone0 不一定是 CPU（虽然你这个基本就是）。

执行：

cat /sys/devices/virtual/thermal/thermal_zone0/type

常见结果：

cpu
soc
mtktscpu

👉 如果是这些，就可以确定：

✅ 这是 CPU / SoC 温度

✅ 更稳的写法（自动找 CPU 温度）
for z in /sys/devices/virtual/thermal/thermal_zone*; do
if grep -qiE “cpu|soc|mtk” z/type; then
echo -n “z: “
awk ‘{printf “%.1f°C\n”, 1/1000}’ z/temp
fi
done
✅ 如果要写程序（嵌入式常用）

直接读：

/sys/devices/virtual/thermal/thermal_zoneX/temp

单位：

m°C（毫摄氏度）

之所以是 m°C 的原因：

这个问题问得很关键，本质是在问：单位依据从哪里来，而不是 “经验猜测”。

结论先给：

thermal_zoneX/temp 的单位是 m°C（毫摄氏度）是 Linux thermal framework 的接口规范定义的，不是某个平台私有约定。

下面给你从规范 → 内核实现 → 实际验证三层证据。

一、内核接口规范（根本依据）

Linux 官方 thermal sysfs 文档明确规定：

/sys/class/thermal/thermal_zone*/temp
单位：millidegree Celsius (m°C)

也就是：

1°C = 1000

这是 ABI 级别约定（用户空间接口），不是驱动随便定义的。

二、内核实现（代码层面）

thermal 框架的核心接口：

int thermal_zone_get_temp(struct thermal_zone_device *tz, int *temp);

这里的 temp：

单位就是 m°C

所有 thermal 驱动（包括 MTK）必须返回这个单位，否则就违反框架约定。

举个典型驱动逻辑（MTK）

在 MTK thermal 驱动（如 mtktscpu）里，本质是：

raw = read_adc (); // 原始值
temp = convert (raw); // 转换成 摄氏度
temp = temp * 1000; // 转成 m°C
return temp;

👉 所以用户空间看到的一定是：

整数 + m°C

三、你当前数据的 “反证法验证”

你读到：

53557

我们做三种假设：

❌ 假设 1：单位是 °C

53557°C

👉 不可能（芯片直接蒸发）

❌ 假设 2：单位是 0.1°C

5355.7°C

👉 仍然不可能

✅ 假设 3：单位是 m°C

53557 / 1000 = 53.557°C

👉 完全符合：

  • SoC 正常温度范围
  • 你设备当前状态

四、再给你一个 “系统级验证方法”

你可以直接验证 thermal trip point：

cat /sys/firmware/devicetree/base/thermal-zones/soc_thermal/trips/crit/temperature

一般输出：

120000

👉 如果单位是 m°C：

120000 → 120°C

✔ 合理（CPU 保护温度）

如果不是 m°C：

120000°C ❌
12000°C ❌

👉 全部不成立

五、再补一个工程细节（很多人不知道）

为什么不用浮点？

  1. 内核禁止浮点运算
  2. 避免精度误差
  3. 统一所有平台接口

所以统一用：

int temp = xxx (m°C)

六、一句话总结

不是我 “判断” 它是 m°C，而是 Linux thermal 子系统 ABI 明确定义：thermal_zone/temp 必须以毫摄氏度表示，所有驱动都必须遵守这个约定。
